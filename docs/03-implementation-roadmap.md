# 实施路线与首版规格

## 1. 阶段安排

以下为完整目标范围的单人学习工作量估算，含已完成的首版工作，不能直接视为剩余工时。P0–P3 约 63–105 小时；全部阶段约 137–227 小时。按每周 10–15 小时投入，完整范围约 10–23 周，实际随经验、环境与模型接入情况变化。

| 阶段 | 依赖 | 估算 | 工作与完成条件 |
|---|---|---|---|
| P0 项目骨架 | 无 | 6–10 小时 | 项目结构、配置、合成数据、模型桩、日志与基本 CI |
| P1 基础问答与契约 | P0 | 12–20 小时 | 入库、向量检索、引用、SSE、测试题集；形成 E01 基线，并完成 E17 的 API 校验子集 |
| P2 Advanced RAG | P1 | 15–25 小时 | 混合召回、改写、重排、分块、版本同步；完成 E02–E06 |
| P3 Pydantic AI 与业务 Agent | P1；推荐 P2 | 30–50 小时 | 接入框架、类型化工具/结果、动态规划、确认、恢复；完成 E07 前两组、E08、E12、E17 |
| P4 多轮与记忆 | P3 | 18–30 小时 | 指代、上下文组装、摘要、跨会话记忆与修正遗忘；完成 E11 |
| P5 MCP 与 Skill | P3 | 14–24 小时 | 本地/协议工具契约、技能加载和版本；完成 E13–E14 |
| P6 多模态与语音 | P4、P5 | 26–42 小时 | 多 Agent 对照、翻译、OCR/ASR/TTS、完整语音回合；补齐 E07，完成 E09–E10、E15 |
| P7 反馈与评测闭环 | P1 起采集；P3、P6 后补齐任务类型 | 10–16 小时 | 反馈入口、复核、Golden Dataset 版本、Eval Pipeline；完成 E16 |
| P8 证据整理 | 各阶段持续记录 | 6–10 小时 | 实验汇总、演示与复现说明 |

Pydantic 校验接口参数，Pydantic AI 实现 Agent。模型通过框架直接接入 DeepSeek；Embedding、ASR/TTS 按能力直接调用相应接口。请求超时、最大任务步数、参数校验和基本错误提示随功能一起实现。当前已接入框架并实现基础闭环，阶段验收仍以完整实验为准，详见实施状态。

## 2. 建议目录

```text

  mcp/                    # MCP Client 适配与本地预算 Server
  skills/                 # 项目技能的发现、匹配和加载
  speech/                 # 录音处理、ASR、TTS、音频结果

docs/adr/                 # 架构取舍
reports/                  # 实验结果
```

## 3. 首个可运行版本：MVP-01

目标：对本地制度文档提问，获得有来源的回答，并能查看检索片段和基本执行结果。

包含：

- 最小对话页，展示流式回答、来源与错误状态。
- 20 份合成 Markdown/TXT 文档，含无答案、版本冲突和过期样本。
- 文档导入、固定分块、向量检索、文档版本和引用定位。
- 一个直接接入的真实模型和确定性 Mock；无密钥时可运行模拟演示。
- 会话保存、无证据拒答、基本应用日志。
- 20 个小型验收样例，P1 扩充为正式评测集。

后续增加混合检索、Pydantic AI Agent、动态规划、记忆、MCP/Skill、翻译、多模态、语音和反馈闭环。MVP-01 的范围保持为首版基线，不将新增能力追溯标记为已实现。

| 编号 | 输入或操作 | 验收结果 |
|---|---|---|
| A01 | 询问制度中的报销上限 | 金额正确，引用定位到原文与版本 |
| A02 | 提问没有依据的问题 | 说明证据不足，不编造规则 |
| A03 | 同名项目存在多个版本资料 | 保留项目与版本信息，必要时请求澄清 |
| A04 | 模型超时或断流 | 页面展示失败或中断状态，可定位错误 |
| A05 | 文档更新并发布 | 新查询使用有效版本，历史引用标明原版本 |
| A06 | 文档删除 | 不再作为新回答依据，引用返回不可用 |
| A07 | 没有配置模型密钥 | Mock 演示和测试可运行，界面标明模拟结果 |

格式、状态和错误路径由 Mock 验证，真实模型的回答质量单独评测，不能用模拟结果代替。

## 5. 决策检查点

| 时点 | 决策 | 依据 |
|---|---|---|
| P0 | 模型与本地组件选择 | 环境可运行性、所需能力与依赖兼容性 |
| P2 | 保留哪些 RAG 改进 | 按题型的检索与回答质量、失败样本 |
| P3 | Pydantic AI 的版本与应用状态机边界 | 工具/输出契约、取消和恢复验证 |
| P4 | 摘要与记忆保留策略 | 关键信息保留、指代、纠正与遗忘实验 |
| P5 | MCP 传输及 Skill 加载方式 | 工具契约一致性、任务匹配与资源完整性 |
| P6 | 多 Agent、多模态及语音引擎选择 | 任务成功率、来源定位、转写与朗读质量 |
| P7 | 哪些反馈进入哪类评测集 | 人工复核、去重、数据隔离与版本对照 |

重要选择写入 ADR：背景、备选方案、实验结果、决定与重新评估条件。

## 6. 完成标准

能从空环境启动，用合成数据完成带记忆的多轮问答、动态规划与模拟审批、MCP/Skill 调用、语音回合及反馈回归演示；引用、任务状态、确认一致性、幂等、恢复与记忆修正测试通过；E01–E17 均有实验记录。语音和 Agent 的质量须使用真实模型验证，Mock 只用于流程与契约测试。未执行部分明确标注未完成。

总结说明哪些能力自建、哪些来自框架，测试数据与实际质量如何，出现哪些失败，以及结果有哪些适用限制。
