# 实验与验收

## 1. 证据规则

每个实验保存 Git commit、依赖版本、模型标识、提示词版本、数据集哈希、实验配置、原始结果和失败样例。外部模型无法固定版本时记录调用日期并说明复现限制。

输出到 `reports/<experiment-id>/<run-id>/`，包含 `manifest.json`、`results.jsonl`、`summary.md` 和必要的步骤记录。下面的阈值是初始学习目标，尚未实测；调整时保留理由，不能看完测试成绩后无说明地修改标准。

## 2. 数据集

| 数据 | 首轮规模 | 内容 |
|---|---|---|
| 合成文档 | 100 份，后续按场景扩充 | 制度、合同、预算说明，包含版本、重复、冲突 |
| 开发问答集 | 60 题 | 调整提示词、切分与检索参数 |
| 验证问答集 | 40 题 | 选择配置 |
| 冻结测试集 | 120 题 | 事实、编号、跨文档、多轮、省略表达、无答案、版本冲突、表格八类，各 15 题 |
| Agent 测试任务 | 30 个，另建开发任务 | 正常、歧义、信息缺失、参数错误、重复提交、超时；每种模式重复 3 次 |
| 翻译样本 | 30 段 | 术语、数字、表格和长句，人工建立评分依据 |
| 多模态样本 | 10 张图片、10 页扫描件、5 段音频、3 段短视频起步 | 标注文本、来源位置与答案依据 |
| 多轮与记忆 | 30 组对话，每组 4–8 轮；另建 10 组长上下文对话 | 指代、切换项目、修正、遗忘、摘要前后关键信息；至少 10 组跨会话 |
| 动态规划 | 20 个场景，每个模式重复 3 次 | 缺字段、改变目标、工具失败、无进展、等待用户后重启 |
| 工具/MCP/Skill | 20 条工具契约、12 个技能匹配任务 | 两种调用方式，同一输入输出；技能缺失、不匹配和版本变更 |
| 语音回合 | 30 条录音及对应回答文本 | 安静/背景噪声/数字编号各 10 条；人工转写和朗读检查依据 |
| 反馈闭环 | 20 条反馈 | 含重复、错误修正建议、待补证据和真实失败，人工给出复核结果 |
| Schema 边界 | 至少 30 条非法或边界输入 | 未知字段、类型错误、空值、超范围金额、无效项目、矛盾状态 |

开发、验证和测试按文档族及业务场景划分，避免同一模板的轻微改写分布在不同集合。每条问答标注相关证据、关键事实和是否应拒答；无答案题不进入普通召回率分母。

合成数据可验证方法，不能直接证明真实企业材料上的效果。若文档扩充，记录文档数、分块数和向量数，避免混用。

## 3. 十七组实验

| ID / 知识点 | 对照方法 | 验收和证据 |
|---|---|---|
| E01 Naive RAG | 向量召回、固定分块、直接生成 | 来源可定位，形成检索与回答质量基线 |
| E02 查询改写 | 关闭、开启、原查询与改写联合召回 | 实体保留、Recall@10、不同问题类别表现 |
| E03 混合召回 | BM25、向量、RRF 混合 | 固定模型与 k，比较 Recall@10 和 MRR |
| E04 Rerank | 同一候选集关闭或开启重排 | nDCG@10、回答质量与排序失败样本 |
| E05 分块与上下文 | 固定长度、结构分块、父子块；去重与上下文上限对照 | 证据完整性、长文与冲突处理 |
| E06 索引生命周期 | 新增、更新、删除、重复入库、单索引失败 | 不使用未发布版本、无重复片段、同步可修复 |
| E07 工作流与 Agent | 确定性流程、单 Agent、多 Agent | 相同工具与步骤上限，比较任务成功率、调用步骤与错误类型 |
| E08 写入与恢复 | 提交前、提交后回执前、结果保存后中断 Worker | 单据唯一，可恢复或明确进入待核对状态 |
| E09 翻译 | 直接翻译、术语工作流、单/多 Agent | 术语、数字、格式保留和人工质量评分 |
| E10 多模态知识 | 转文本路线与原生多模态路线 | OCR/ASR 错误率、答案质量与来源定位 |
| E11 多轮与记忆 | 无历史、最近轮次、摘要、摘要加长期记忆 | 指代正确率、事实保留、跨会话使用、修正与遗忘后的行为 |
| E12 动态规划 | 固定计划、可重新规划的 Pydantic AI Agent | 目标切换与故障后的任务成功率、计划调整、停止与恢复 |
| E13 Tool Calling 与 MCP | 同一预算工具分别进程内调用、stdio MCP 和 HTTP MCP | 参数与结果一致、断连和结构错误、未知写入不重复执行 |
| E14 Skill | 不加载、固定加载、按需加载 | 技能选择、模板遵循、无关任务不误触发、版本与资源处理 |
| E15 语音交互 | 文本输入、原始 ASR、修正后 ASR；文本与 TTS 对照 | 转写、关键字段、端到端任务结果、朗读正确与音频可播放 |
| E16 反馈与评测闭环 | 从原始反馈到人工复核、样本发布、版本回归 | 可复现错误、错误反馈不入库、数据隔离、新旧版本可比较 |
| E17 Pydantic 与 Agent 契约 | API 参数、工具输入、Agent 结构化输出三层校验 | 非法值拒绝、修正次数有限、事实与业务校验、SSE 终态一致 |

E01–E05 先做单因素对照，再验证累积组合。保持语料、生成模型、提示词和题集一致；改变上下文上限时单独标记，不把更强模型带来的收益归因于检索策略。

## 4. 指标与初始目标

### 检索和回答

- Recall@k：前 k 个结果命中的相关证据单元数 / 标注相关证据单元总数，按题宏平均；重复块不重复计数。
- MRR：首个相关结果排名倒数的平均值；没有命中记 0。
- nDCG@k：以标注的相关等级评价排序，保存标注规则。
- 回答通过率：关键事实完整、事实正确、引用支持三项全部通过的题目比例。
- 引用支持率：有证据支持的可核查陈述 / 所有需要证据的陈述。
- 拒答正确率与误拒率分别统计，不用总体均分掩盖无答案场景。

初始目标为可回答题 Recall@10 ≥ 85%、回答通过率 ≥ 80%，同时报告样本量和各题型表现，不预先承诺截图中的 97%。

格式、数字、实体和引用定位由程序检查；语义质量由人工按固定规则评价，LLM Judge 只做辅助。基线与最终对照使用同一标准评价全部测试题，保留分歧和失败样本。

### Agent 与业务结果

- 任务成功率：达到预期业务终态，且满足证据、唯一写入和确认一致性要求的任务比例。
- 重复副作用率：发生重复单据的任务 / 涉及写入的任务。
- 恢复成功率：故障后恢复到正确终态的任务 / 可恢复故障任务；需人工核对的任务单列。
- 辅助指标：模型调用次数、工具调用次数、步骤数和人工介入次数，用于解释流程行为。

以模拟业务数据库的状态为准，不以模型声称“已完成”为准。首轮目标为每轮 30 个任务至少 24 个成功，幂等与确认一致性关键用例全部通过；重复三轮分别报告。

### 翻译与多模态

翻译记录术语正确率、数字与实体保留率、格式检查结果，并按人工评分标准评价准确性和流畅度。明确“提升”指绝对百分点还是相对变化。

OCR 采用字符错误率，ASR 按语言选择字符或词错误率并固定分词规则；同时评测端到端问答。来源定位检查页码、原图或时间段是否支持结论，不能只评价转写文本。

### 新增能力的验收口径

| 实验 | 指标与初始门槛 |
|---|---|
| E11 | 30 组多轮对话至少 24 组正确解析指代及项目；摘要关键事实保留率 ≥ 90%；所有已标注的记忆修正、删除及跨项目隔离用例通过 |
| E12 | 每轮 20 个任务至少 16 个达到预期终态；无进展能停止；修改目标后不执行旧项目写入；三轮分别报告 |
| E13 | 20 条契约在本地函数与两种 MCP 传输下结果一致；退出、重连、非法结果和结果未知的必测场景全部通过 |
| E14 | 12 个任务至少 10 个正确选择技能或选择不加载；缺失资源与不兼容版本有明确处理，不能悄悄套用错误模板 |
| E15 | 30 条录音分别报告 CER/WER 与关键字段准确率；用户修正后关键项目/金额全部一致；朗读不得改变金额、否定词及业务含义，所有音频可播放 |
| E16 | 20 条反馈全部可追溯；复核决定与人工标注一致；重复和错误反馈不直接成为 Golden Dataset；完成一次数据版本发布与新旧配置回归报告 |
| E17 | 30 条非法或边界输入全部按约定处理；结构错误不标记成功；结果修正最多两次；类型正确但引用不存在的输出也必须被拒绝 |

上述均为学习项目的初始目标，不是已实现结果。TTS 自然度采用 1–5 分人工听感记录并说明评分者与样本，不把 ASR 回转写通过等同于音频质量合格。正式语音指标以真实引擎测试为准。

E11 的摘要事实单位必须预先标注；“记得更多”不能代替可核查事实保留率。E12 不要求逐步计划与参考答案完全相同，以业务终态和必要约束判断。E13 验证原始 MCP 返回结果和领域模型映射，不能仅依赖框架报告调用成功。

## 5. 必测功能边界

| 用例 | 输入或干预 | 预期 |
|---|---|---|
| 项目歧义 | 多个同名项目 | 请求选择，不直接提交任一项目的草稿 |
| 无答案 | 知识库没有依据 | 明确说明缺少依据 |
| 版本冲突 | 新旧制度给出不同结论 | 使用有效版本，必要时说明冲突 |
| 删除延迟 | 元数据已删除而索引未清理 | 不进入回答，引用返回不可用 |
| 参数错误 | 工具参数缺字段、类型或范围错误 | 校验失败并返回可修正信息 |
| 确认后修改 | 草稿金额或业务版本发生变化 | 旧确认失效，重新展示并确认 |
| 重复提交 | 重复确认、重试、Worker 重启 | 同一幂等操作只产生一个单据 |
| 提交结果未知 | 业务成功后回执丢失 | 按幂等键核对结果，不盲目创建 |
| 模型断流 | 输出前或输出中断开 | 有限重试或明确中断，不重复追加答案 |
| 指代与目标切换 | 先查 P1001，再说“它”“换成 P2002” | 正确绑定项目，旧草稿失效 |
| 摘要与工具消息 | 在工具调用之后触发上下文裁剪 | 不留下孤立工具结果，不丢失必要编号和确认状态 |
| 记忆纠正/遗忘 | 更新偏好或删除已保存记忆 | 后续任务与摘要不继续使用旧值 |
| 重新规划无进展 | 工具重复返回相同结果 | 达到约定上限后停止并说明缺失信息 |
| MCP 重连 | 写入成功后连接中断 | 核对幂等键，不重放创建操作 |
| Skill 不匹配 | 普通制度问答误匹配预算审查技能 | 选择不加载，不执行无关流程 |
| 语音关键字段错误 | ASR 将 P1001/金额识别错误 | 用户可修正，未确认草稿不直接提交 |
| TTS 失败 | 合成服务返回错误 | 文本答案和引用保留，音频明确失败 |
| 错误用户反馈 | 用户提供与制度不符的“正确答案” | 复核拒绝或要求补充依据，不污染标准答案 |
| Schema 合法但事实错误 | 草稿金额为合法正数，却与预算计算不符 | 领域规则拒绝，不能仅按类型验收 |

这些用例检验功能正确性和任务恢复，不以生产规模指标作为验收条件。

## 6. 报告与最终证据

每份报告包含：问题与假设、数据集、基线配置、变更因素、质量结果、失败样本、限制、结论与是否采用。结果应能追溯到原始记录。

最终交付：可启动环境、端到端演示、E01–E17 实验报告、测试清单、架构取舍和可复现说明。没有改善的实验也保留记录。截图中的效果数字不作为本项目已经实现的成果。

E16 的报告必须包含反馈 ID → 复核记录 → 样本 ID → 数据集版本 → 评测运行 ID 的关联。新旧配置在相同冻结测试集上配对比较，同时单列已知问题回归集结果；参与调参的反馈样本不能算作独立测试收益。
