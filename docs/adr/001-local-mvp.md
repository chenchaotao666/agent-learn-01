# ADR-001：首版使用 SQLite 与可替换的向量生成方式

状态：首版采用；后续按阶段复评。

## 背景

仓库最初仅有设计文档。首个交付需要在 Windows 上无需额外服务即可跑通文档导入、检索、回答与引用，并保留接入真实模型的路径。

## 决定

- 使用 SQLite 保存元数据、版本、会话与向量，不先启动 PostgreSQL/Qdrant。
- 固定字符窗口分块；默认以字符二元组哈希生成 1024 维向量并做 L2 归一化，用余弦相似度检索。
- 默认 Mock 仅摘录原文，页面与报告明确标注模拟结果。
- 可选直接调用 Ollama `/api/embed` 和 `/api/chat`，无中间模型服务。
- 每份文档的向量记录所属生成方式和模型配置，检索不混用不同向量空间。
- 入库先生成全部向量，再以事务发布文档及分块；失败不会改变现有版本。

## 影响

默认无需下载模型即可演示与测试。字符哈希不理解语义，会有误召回和漏召回，不能充当真实 Embedding 效果证据。全量扫描向量仅适用于当前小型实验数据集。

变更向量模型时暂采用新数据库重新导入。当前没有后台重建索引功能。历史会话保存当时的回答，引用读取时重新检查文档是否已删除。

## 复评条件

真实 Embedding 联调后，按正式 E01 评测验证质量；进入 P2 前接入 Qdrant 和 ES，并保留同一数据集与质量指标做对照。
